# 개인 Cloudflare 설치

화면은 제작자의 포켓몬 전용 Cloudflare Pages에서 제공하고, 노션 기록 API는 각 사용자의 Cloudflare Worker에서 처리합니다. 공부 기록 위젯과 같은 공용 화면·개인 API 구성입니다. 실제 Pages/Worker 배포와 노션 연결은 아직 수행하지 않았습니다.

## 사용자 설치 흐름

1. 노션에서 빈 페이지를 하나 만들고 내부 연결을 생성합니다. 연결에 콘텐츠 읽기·삽입·업데이트 권한을 부여하고, 페이지의 `··· → 연결 추가`에서 연결을 추가합니다.
2. 배포 화면에서 세 가지를 입력합니다.

| 입력 | 내용 |
|---|---|
| NOTION_TOKEN | 노션 내부 연결 토큰 |
| NOTION_PARENT_PAGE_ID | 수집 도감을 만들 노션 페이지 주소; 페이지 ID도 가능 |
| WIDGET_KEY | 32자 이상의 무작위 개인 위젯 키. 노션 토큰과 다른 값 |

3. 제작자가 제공하는 공용 Pages의 `/setup.html`을 엽니다. 본인의 Worker 주소와 WIDGET_KEY를 입력하고 연결 버튼을 누릅니다. 노션 DB와 속성은 자동 생성됩니다. 개인 Worker 주소에 `/setup.html`을 붙여 열지 않습니다.
4. 만들어진 개인 위젯 주소를 노션에 붙여넣고 임베드를 선택합니다.

WIDGET_KEY는 충분히 무작위인 값을 사용하세요. 개인 임베드 주소에는 Worker 주소와 이 키가 포함되므로 본인의 비공개 노션 페이지에서만 사용합니다. 키는 URL의 `#` 뒤에 있어 Pages 요청 주소·Referer에 포함되지 않으며, 개인 Worker API 요청에는 Authorization 헤더로 전송합니다. 노션 API 토큰은 위젯에 전송하지 않습니다.

## 제작자 배포 템플릿 준비

현재 파일은 https://github.com/loraticon/random_pokemon_widget-test 에 게시한 배포 준비본입니다. 먼저 제작자 Pages를 배포하고, 실제 공용 origin을 `cloudflare/worker.wrangler.jsonc`의 `WIDGET_ORIGIN`에 한 번 지정해야 합니다. 이 값은 사용자마다 달라지는 secret이 아니라 공용 화면의 허용 주소입니다. 현재는 주소가 확정되지 않아 빈 값이며, 미설정이면 Worker가 연결을 거절합니다. 자세한 단계는 [제작자 Pages 안내](공용-Pages-배포.md)를 참고하세요.

공용 화면은 루트 `wrangler.jsonc`의 Pages 설정을 사용하고, 개인 API는 `cloudflare/worker.wrangler.jsonc`의 Worker·SQLite Durable Object 설정을 사용합니다. `.dev.vars.example`은 개인 API에 등록할 세 가지 secret의 안내입니다. 실제 Deploy to Cloudflare 버튼은 개인 API 템플릿의 공개 저장소·배포 경로를 확정한 뒤 추가합니다. 이 저장소에는 공용 Pages와 개인 API의 준비 파일이 함께 있지만, 배포는 각각 진행합니다. `npm run build`는 공용 Pages 파일을 만들고, `npm run deploy`는 개인 API만 배포합니다.

무료 플랜을 유지하세요. 유료 플랜, R2 등 추가 유료 서비스를 사용하지 않는 구성입니다. 무료 한도를 넘으면 해당 요청/작업이 실패할 수 있습니다. 자동으로 무제한 운영이 보장되는 방식은 아닙니다.

## 개발자 CLI 설치

```powershell
npm install
npx wrangler login
npx wrangler secret put NOTION_TOKEN --config cloudflare/worker.wrangler.jsonc
npx wrangler secret put NOTION_PARENT_PAGE_ID --config cloudflare/worker.wrangler.jsonc
npx wrangler secret put WIDGET_KEY --config cloudflare/worker.wrangler.jsonc
npm run deploy
```

제작자가 템플릿에 지정한 WIDGET_ORIGIN을 유지하세요. 다른 허용 주소를 사용할 경우 Worker의 변수 값을 해당 공용 HTTPS origin으로 변경해야 합니다. 계정 로그인·secret 등록·실제 배포 명령은 실행하지 않았습니다. 토큰을 채팅이나 저장소에 붙여넣지 마세요. 로컬 API 개발은 `.dev.vars.example`을 `cloudflare/.dev.vars`로 복사해 값을 채운 뒤 `npm run dev`로 진행합니다. 제작자 공용 화면의 빌드는 `npm run build`입니다.

## 저장과 복구

2026-10-04 최소 속성·즐겨찾기 업데이트는 **공용 Pages와 개인 Worker 양쪽을 재배포**합니다. 기존 Worker와 Durable Object를 유지하면 수집 기록·기회·메인화면 설정을 보존하면서 업데이트할 수 있습니다. 새 `포켓몬 수집 기록` DB에는 다음 네 속성만 만듭니다.

| 속성 이름 | 노션 속성 유형 | 예시 |
|---|---|---|
| 이름 | 제목 | 피카츄 |
| 폼 식별자 | 텍스트 | pikachu |
| 배경 식별자 | 텍스트 | electric |
| 즐겨찾기 | 체크박스 | 체크하면 포켓몬 즐겨찾기에 표시 |

잡은 포켓몬은 기존처럼 노션에 자동 추가합니다. 이미지 주소·도감 번호·타입은 저장하지 않고 위젯의 목록에서 불러옵니다. 잡은 날짜는 노션 페이지의 생성 시각을 사용합니다. 배경 식별자를 비워 두면 포켓몬에 맞는 기본 배경을 사용하며, 등록된 다른 식별자로 바꾸면 해당 배경을 불러옵니다.

포켓몬 즐겨찾기는 노션 체크박스를 읽고, 위젯의 별 버튼도 같은 체크박스를 업데이트합니다. 배경 즐겨찾기와 선택한 포켓몬·배경·모드는 개인 Worker의 Durable Object에 저장합니다. 모드나 배경 설정을 저장할 때 포켓몬 즐겨찾기를 덮어쓰지 않습니다. 실제 노션·기기 간 동기화는 배포 환경에서 별도로 검증해야 합니다.

기존 DB에는 빠진 필수 속성만 추가하며, 예전 속성을 삭제하지 않습니다. `즐겨찾기` 속성을 새로 추가할 때 이전 Worker에 저장된 일반 포켓몬 즐겨찾기를 체크박스로 한 번 옮깁니다. 색이 다른 포켓몬은 새로 뽑거나 저장하지 않으며, 기존 색이 다른 기록은 삭제하지 않고 위젯에서 숨깁니다.

- 하루 세 마리는 한국 시간 기준으로 서버가 확인합니다. 뽑기와 아니오는 차감하지 않습니다.
- 각 포획은 고유 요청 ID를 가집니다. 같은 요청을 재시도해도 노션에 두 번 만들지 않습니다.
- 이미 잡은 포켓몬은 새 요청 ID나 다른 기기로도 중복 포획할 수 없습니다. 폼을 구분하고, 중복 요청은 기회를 차감하지 않습니다. 기존 저장 기록도 업데이트 시 이 규칙에 반영합니다.
- SQLite Durable Object가 동시에 들어오는 포획을 순서대로 처리합니다. 확정 저장 전에는 기회를 예약하고, 저장 성공 후 밝은 볼을 표시합니다.
- 노션이 명확히 저장을 거절하면 예약을 해제합니다. 타임아웃/서버 오류처럼 저장 여부가 불분명하면 다시 POST하지 않고 `폼 식별자`로 기존 기록을 조회합니다. 요청 ID는 Worker에 보관하며 노션 속성은 필요하지 않습니다. `저장 상태 확인`으로 복구할 수 있습니다.
- 불분명한 요청이 노션에 계속 나타나지 않으면 안전상 예약 상태를 유지합니다. 자동으로 재생성하면 늦게 처리된 요청과 중복될 수 있기 때문입니다. 이 경우 Cloudflare 저장소와 노션의 실제 기록을 확인하는 운영자 복구가 필요합니다.
- 노션에서 기록을 삭제해도 이미 사용한 당일 기회나 해당 포켓몬의 포획 이력은 초기화되지 않습니다. 위젯 도감은 다시 열거나 ↻를 눌렀을 때 노션의 현재 기록을 읽습니다.
- DB 이름과 자동 생성한 속성 이름을 변경하면 연결이 실패할 수 있습니다. 위젯을 업데이트할 때는 동일 Worker와 Durable Object 저장소를 유지합니다.
- PC에서 HTML을 더블클릭한 미리보기는 브라우저 저장소를 사용합니다. 실제 노션 동기화와 다른 기기 공유는 배포한 위젯에서만 작동합니다.
- 화면 디자인 업데이트는 제작자의 Pages에서 배포합니다. 개인 API 코드가 바뀌는 업데이트만 사용자의 Worker 재배포가 필요합니다. 무료 한도는 사용자 계정의 다른 Worker와 공유합니다.
